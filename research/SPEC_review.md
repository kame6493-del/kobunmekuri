# 古文単語データの検査(2回目・書いた人とは別の観点で)

APP = `C:\Users\yuichi1\Downloads\こぶんめくり_2026-10-03\app\`

書いた人は「候補の例文から1つ選び、意味と訳を書く」観点で作った。検査では次の観点で全語を1語ずつ見直す。入試で間違えて覚えさせることが最悪の失敗なので、迷ったら直す側に倒す。ただし好みの言い換えだけの変更はしない。

## 見ること
1. 意味(means)を、一般的な古語辞典の語義と照らす。誤った語義・入試で必須の語義の欠落・順番(先頭が最重要)の誤り。現代語の意味だけを書いて古語の意味が抜けていないか。
2. quiz(4択の正解に出す短い意味)が、その語の最重要の語義になっているか。別の語の意味と取り違えていないか。
3. 例文の hit が本当に見出し語か(同じ字面の別の語・別の活用語の一部・複合語の一部を拾っていないか)。sentences.jsonl で前後の文を見て文脈を確かめる。
4. ex.sense が、その例文での使われ方と一致しているか。訳(ex.tr)が原文に対して正しいか(主語・敬語・助動詞の意味・打消の取り違え)。
5. note に事実の誤り(語源のこじつけ・作品名や人物の誤り・活用の種類の誤り)が無いか。
6. 品詞(pos)と cat が明らかにおかしくないか。

## 出力
`APP\research\review\review_<担当>.json` に、直す所だけを配列で書く(直す所が無い語は書かない):

```json
[{"rank": 12, "w": "語", "field": "means", "new": ["新しい意味1", "意味2"], "reason": "古語辞典の語義では…"}]
```
- field は means / quiz / note / pos / cat / ex.tr / ex.sense / ex のどれか。ex は例文を差し替えるとき({sid,text,hit,tr,sense} 全体。text は sentences.jsonl の文の連続した一部をそのまま)。
- means を変えて番号がずれるときは、ex.sense も合わせて直す行を足す。
- 文字数の決まり: means 各20字以内・1〜4個、quiz 14字以内、note 30〜180字、tr 4〜120字。マークダウンの太字記法と絵文字は使わない。
- 元のデータファイル(research\batches\*.json)は書き換えない。読むだけ。
- 作業用の一時ファイルは APP\research\review\tmp_<担当>\ に置く(共有の scratchpad は他の作業者と衝突するので使わない)。
- 終わったら、直した数を分類別(意味の誤り/quiz/例文の取り違え/訳の誤り/解説の誤り/その他)に数えて報告する。
